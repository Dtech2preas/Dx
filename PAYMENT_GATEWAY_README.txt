# D-TECH Secure Payment Gateway Integration Guide

This guide explains how to integrate your website/service (within `*.dtech-services.co.za` or `*.preasx24.co.za` domains) with the D-TECH Voucher Payment Gateway.

## Overview of Payment Flow

1. **Initiate Payment:** Your website redirects the user to `payment.html` with specific query parameters.
2. **User Input:** The user enters their D-TECH voucher code on the payment page.
3. **Processing:** The D-TECH backend securely verifies and marks the voucher as used.
4. **Redirect Back:** The user is redirected back to your website with a secure, one-time `token`.
5. **Server Verification:** Your website securely calls the D-TECH backend to verify the `token`.
6. **Fulfillment:** Only after successful verification, your website unlocks the product/service for the user.

---

## Step 1: Redirect User to Payment Page

When a user clicks "Buy" on your website, you must redirect them to `payment.html` hosted on the central D-TECH domain.

**Example URL:**
`https://student.dtech-services.co.za/payment.html?amount=30&item=Premium+Tool&order_id=ORD-998&return_url=https://tools.dtech-services.co.za/success`

**Required URL Parameters:**
*   `amount`: The exact price in Rand (e.g., `30`). **Vouchers must match this amount exactly.** Any extra value on the voucher is forfeited.
*   `item`: The name of the product/service the user is buying.
*   `order_id`: A unique Order ID generated by your website.
*   `return_url`: The full URL on your website where the user should be redirected after a successful payment.

---

## Step 2: Handle the Redirect Back

After a successful payment, `payment.html` will automatically redirect the user back to your `return_url`.

**It will append the following parameters to your URL:**
*   `status=success`
*   `token=SECURE_TOKEN_STRING`
*   `order_id=YOUR_ORDER_ID`

**Example Return URL:**
`https://tools.dtech-services.co.za/success?status=success&token=12345-abcd-6789&order_id=ORD-998`

⚠️ **CRITICAL SECURITY WARNING:**
Never trust the `status=success` parameter alone. A malicious user can manually type this into their browser. **You MUST verify the token via a backend API call.**

---

## Step 3: Verify the Payment (Server-to-Server)

Before giving the user the product, your website's backend/server must call the D-TECH Worker to verify the `token`.

**Endpoint:** `POST https://dark-mud-87fb.jonasmochebane.workers.dev/verify-payment`

**Request Headers:**
*   `Content-Type: application/json`

**Request Body (JSON):**
```json
{
  "token": "SECURE_TOKEN_STRING",
  "order_id": "YOUR_ORDER_ID"
}
```

**Response (Success):**
If the payment is valid and the token hasn't been used before, you will receive a 200 OK:
```json
{
  "valid": true,
  "amount": 30
}
```

**Response (Error):**
If the token is invalid, expired, already verified, or the `order_id` doesn't match, you will receive a 400/404 Error:
```json
{
  "error": "Token has already been verified"
}
```

---

## Important Rules

1. **Exact Value Matching:** The system enforces that the voucher value exactly matches the requested `amount`. If a user needs to pay R30 but enters an R50 voucher, the transaction will process, but the remaining R20 is permanently lost. The UI warns users of this.
2. **One-Time Use Vouchers:** Vouchers can only be redeemed once.
3. **One-Time Use Tokens:** The `token` provided in the redirect is single-use. Once your backend calls `/verify-payment` successfully, the token is marked as verified and cannot be used again. This prevents replay attacks.
4. **Allowed Domains (CORS):** The D-TECH backend automatically allows requests originating from any subdomain of `.dtech-services.co.za` and `.preasx24.co.za`.
